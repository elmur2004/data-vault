The count and its date are one cell. The figure is 14px semibold with tabular figures; the as-of date is 11.5px at ink 60 on the same line, so it wraps with the number and can never be read alone. Rows are 56px here rather than 52px to hold two lines.

An active filter is violet and states the count. “3 of 5 sheets” plus one clear filter action next to the filters — the same control that appears in the no-results state, in the same place, so it is already familiar when the table is empty.

Preview is the primary control, download the secondary one. Row one shows the pressed state. A DOCX has no preview, so the slot holds an em dash at ink 30 rather than a disabled button nobody can explain.

8

The viewer sits on mist, not on black. The page keeps its own 1px edge and a soft shadow so it reads as paper. Identity — name, type, company, size, date — stays in the dialog header, because a preview opened from search needs to say what it is.

Escape closes, arrows page. Focus is trapped in the dialog and returns to the row's preview button on close. On mobile the toolbar drops zoom — pinch does that — and keeps paging plus one 44px download.

10

Overdue is a chip, not a colour wash. A passed deadline on an open task gets an orange-100 chip with #D94E18 semibold text — legible at 12.5px, and the row stays white so four overdue rows do not turn the table orange. The card count uses the same chip.

11

Late is blank while a task is open. It is written once, at completion, and stored — so the last two rows read “On time” and “Late by 3 days” and will not change if an admin edits the deadline afterwards. An open overdue task shows nothing in Late; the deadline chip is doing that work.

12

Completed rows recede. Ink 60 text, name struck through, and a 2% ink wash — visible, sortable, never competing with what is still owed. Default sort is open first, then deadline ascending, so the next thing due is always the first row.

13

One card open at a time, expanded in place. The open card gains a violet border and a violet-100 head so the page still shows which person you are inside. The checkbox on row one carries the focus ring: this table is walked with Tab and Space.

14

Result is a preview plus counts. One line of the text, truncated, with “3 files” and “1 link” beneath it. The counts are the honest summary: they say a result exists and how much of it there is without opening anything.

15

Mobile keeps the checkbox and adds the words. Deadline is the first pair, because it is why anyone opens this screen on a phone. Each open task also carries the explicit button — the same action as the checkbox, named. An employee sees one card, already expanded, and no other names.

Buildable as specified

Every table here is a TanStack Table with column definitions matching the headers shown; every dialog is a Radix dialog with focus trapped and Escape bound; filters are shadcn select and toggle groups. The four section tables share one column-renderer set, which is why they look the same and why the mobile card is written once.

Responsive rules

One breakpoint carries the weight: below md the sidebar becomes a drawer, the header collapses to hamburger, mark, search and avatar, every table becomes the stacked card from Foundations, and dialogs go full screen with a sticky action. Nothing scrolls horizontally at 375px. Touch targets are 44px, desktop icon buttons 32px.

Kept for translation

Every string is a key, no text is drawn into imagery, and all spacing uses logical properties — padding-inline, border-inline-start, margin-block — so the whole interface mirrors under dir="rtl" without a second layout. Dates render through one formatter; figures are tabular everywhere.
